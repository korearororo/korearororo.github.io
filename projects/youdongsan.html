기존 회사 시스템 전체를 단독 개발했다는 뜻은 아닙니다. 아래에는 제가 맡아 수정·검토한 범위를 적었습니다.

01 / 공시 기반 AI 보고서

읽기 좋은 문장보다, 근거 있는 판단이 먼저였습니다

기존 시스템은 공시자료를 바탕으로 기업 분석 보고서를 만듭니다. 하지만 문장이 자연스러워도 원문에 없는 추세나 인과관계를 덧붙이면 판단에 쓰기 어렵습니다. 저는 생성된 보고서가 입력 자료에 기대어 말하는지 확인하고, 교정본이 원래의 사실·수치·판단을 보존하는 기준을 보완했습니다.

  1. 입력기업 공시자료금액·통화·만기일과 서술의 출처
  2. 기존 흐름AI 분석 보고서입력을 바탕으로 만든 초안
  3. 제가 보완근거·내용 검증원문에 없는 판단과 교정 중 의미 변화 확인
  4. 결과검토된 본문 반영기준을 통과한 교정본만 저장
01

사실 검증과 문체 교정을 분리

금액·통화·만기일과 판단의 근거를 먼저 대조했습니다. 표현을 다듬은 뒤에는 사실·수치·원문의 의미가 남아 있는지 다시 확인하도록 흐름을 정리했습니다.

02

같은 입력으로 결과를 다시 확인

고정 입력으로 보고서를 대조하고 재검토 대상은 별도 단계에서 확인했습니다. 모델·추론 강도에 따른 누락, 처리 시간, 토큰·추정 비용도 비교해 운영 후보를 검토했습니다. 특정 모델의 우위나 전체 정확도 향상률로 일반화하지 않았습니다.

검증 기준을 바꾼 사례

‘회복’이라고 쓰려면 이전 상태가 필요합니다

보고서에 ‘영업현금흐름 회복’이라는 표현이 있었지만 입력 자료에는 과거 현금흐름의 추이가 없었습니다. 그 근거가 없다면 문장이 자연스럽거나 조건절로 쓰였더라도 ‘회복’이라고 판단할 수 없습니다. 이 전제를 검증 기준에 명시하고, 사실 판단과 문체 교정의 결과를 따로 검토했습니다.

작업에서 배운 기준

AI가 그럴듯하게 요약했는지보다, 원문으로 다시 확인할 수 있는 판단인지가 중요했습니다. 저장 오류가 난 분석 결과는 생성 문제와 후처리 문제를 구분해 기존 응답을 재사용했지만, 이는 보고서 검증 흐름을 보완한 작업의 일부입니다.

02 / 부동산 조사 도구

서로 다른 자료를 같은 기준으로 비교하도록

부동산을 조사할 때 거래 사례는 공공데이터에, 건물 정보는 건축물대장에, 면적·시세 정보는 별도 서비스에 흩어져 있습니다. 조사자가 주소나 지도에서 대상 위치를 정하고 기간·반경·유형을 선택하면, 관련 자료를 찾아 비교표와 지도 보고서로 내보내는 로컬 도구를 개발했습니다.

  1. 01본건 지정주소·건물명 검색 또는 지도 선택
  2. 02주변 사례 조회기간·반경·부동산 유형 설정
  3. 03기준 맞추기거래일·면적·가격과 자료 출처 구분
  4. 04비교표 작성지도와 함께 PDF·Word·Excel 등으로 저장
01

조회에서 보고서 출력까지 연결

실거래가·건축물대장·KB 정보의 조회 경로와 면적 환산, 전용률·평단가 계산, 비교표 작성과 파일 내보내기를 구현·보완했습니다. 조사자가 원본 항목을 확인한 뒤 필요한 값만 표에 남길 수 있습니다.

02

비슷해 보이는 값을 섞지 않기

과거 개별 거래의 실거래가와 현재 단지 평균 호가는 같은 값이 아닙니다. 자료의 시점과 면적 기준을 구분해 표시하고, 지번이 가려진 거래를 특정 부지의 거래로 단정하지 않도록 했습니다.

부동산 조사 도구기존 조사표의 실거래 표본과 거래일·가격·면적을 대조했습니다.과거 개별 호가를 현재 단지 평균으로 재현할 수는 없습니다.
