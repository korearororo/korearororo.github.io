유동산 업무 자동화

AI 보고서의 근거를 확인하고 저장 오류를 복구했습니다.

공시자료를 바탕으로 만든 보고서가 원문에 없는 판단을 담지 않도록 확인했습니다. 저장 과정에서 오류가 난 결과는 이미 받은 응답을 활용해 복구했고, 실거래 조회와 비교표 작성도 개선했습니다.

일의 배경

보고서의 문장과 숫자를 어디까지 믿을 수 있을까

담당
AI 보고서 검증 · 처리 흐름 개선 · 시세조사 자동화
재처리
저장 실패 2건을 기존 응답으로 복구 · 최종 275건 저장
표본 대조
기존 조사표 5개에서 거래 35건 확인

문제

AI 보고서에는 자연스럽지만 입력 자료에서 근거를 찾을 수 없는 표현이 섞였습니다. 분석 응답을 받은 뒤에도 저장 과정의 단위 처리 오류로 결과를 다시 확인해야 했습니다.

해결 방향

원문과 판단을 연결하는 검증 기준을 구체화하고, 기존 응답을 다시 활용할 수 있도록 후처리와 저장 흐름을 보완했습니다. 시세조사에는 여러 데이터 소스를 연결하고 기존 업무자료와 대조하는 절차를 적용했습니다.

제가 맡은 일

검증, 복구, 시세조사 흐름을 맡았습니다

01

원문 근거를 확인하는 보고서 검증

금액·통화·만기일과 판단 근거를 입력 자료와 대조했습니다. 글머리표별 근거 형식과 문체를 정리하고, 2차 교정 과정에서 사실·수치·원문의 의미가 보존되는지 확인하는 기준을 보완했습니다.

02

기존 응답을 재사용한 오류 복구

Batch 결과의 외화 단위 처리 오류를 수정하고 기존 응답을 재처리했습니다. 기존 273건을 유지하고 실패 2건을 추가 AI 호출 없이 복구해 최종 275건의 DB 저장을 완료했습니다. 모델·추론 강도별 품질, 처리 시간, 토큰 사용량과 비용도 비교했습니다.

03

주변 거래 조회와 비교표 자동화

주소나 지도에서 조사 위치를 지정하고 기간·반경·유형으로 거래를 찾도록 개발했습니다. 실거래가·건축물대장·KB 정보를 연결하고, 면적 환산·전용률·평단가 계산과 내보내기를 정비했습니다.

구현 판단

이미 받은 AI 응답을 다시 쓰기로 했습니다

처리 흐름

공시 입력 → AI 분석 응답 → 사실·수치·표현 검토 → 단위 후처리 → DB 저장

오류가 난 단계부터 복구

오류는 모델 응답이 아닌 저장 단계에서 났고, 기존 응답은 남아 있었습니다. 그래서 이미 저장한 273건을 다시 처리하지 않고 실패한 2건만 복구했습니다.

검증 기준을 명시

‘회복’처럼 과거 상태를 전제하는 표현은 과거 추이가 입력에 있는지 확인합니다. 문장이 자연스러운지와 근거가 충분한지를 나눠 판단했습니다.

표본 검증의 범위

기존 조사표 5개에서 아파트 20건·오피스텔 6건·상가 9건을 대조했습니다. 거래일·가격·면적 확인 결과이며 전체 데이터의 정확도 측정은 아닙니다.

실제 오류 사례

근거 없이 쓰인 ‘영업현금흐름 회복’

01

발견

보고서에는 ‘회복’이 쓰였지만 입력 자료에는 과거 현금흐름의 수준과 추이가 없었습니다. 재검증 결과도 달라졌습니다.

02

판단과 수정

‘회복’은 이전의 부진을 전제하므로 그 근거가 없으면 조건절에 쓰여도 오류로 판단하도록 기준을 명시했습니다.

03

기록

검증 지침과 실행 버전을 구분해 수정 내역과 비교 결과를 남겼습니다. AI 판정과 원문 근거 확인을 함께 검토했습니다.

확인한 결과

복구한 건수와 자료를 대조한 범위

275건

기존 273건에 저장 실패 복구 2건을 더한 Batch 최종 저장 수

35건

아파트 20건 · 오피스텔 6건 · 상가 9건에서 거래일·가격·면적 대조

시점 구분

실거래가와 현재 호가를 구분해 표시하고 과거 개별 매물은 별도 확인

구현 범위와 남은 확인 사항

35건은 기존 조사표 5개에서 대조한 표본입니다. 275건은 기존 273건과 복구한 2건을 합친 최종 저장 수입니다. 이 수치를 전체 정확도나 시간 절감률로 해석하지 않습니다. 공개 페이지에는 회사 내부 원문·고객 정보·실제 보고서와 소스코드를 싣지 않았습니다.
