실제 오류 사례

‘회복’이라고 썼지만, 이전 수치가 없었습니다

공시자료를 바탕으로 만든 AI 보고서의 문장을 원문과 대조하며 발견한 사례입니다. 자연스러운 표현이어도 이전 상태를 확인할 자료가 없으면 근거가 부족합니다.

01

발견

보고서에는 ‘회복’이 쓰였지만 입력 자료에는 과거 현금흐름의 수준과 추이가 없었습니다. 재검증 결과도 달라졌습니다.

02

판단과 수정

‘회복’은 이전의 부진을 전제하므로 그 근거가 없으면 조건절에 쓰여도 오류로 판단하도록 기준을 명시했습니다.

03

기록

검증 지침과 실행 버전을 구분해 수정 내역과 비교 결과를 남겼습니다. AI 판정과 원문 근거 확인을 함께 검토했습니다.

실제 처리 흐름

AI가 만든 문장과 저장 결과를 따로 확인했습니다

공시자료를 바탕으로 보고서를 만드는 기존 시스템에서 분석 결과를 검토하고 후처리·저장 오류를 다뤘습니다. 보고서의 자연스러운 표현은 원문 근거와 별도로 판단했고, DB 저장 성공 여부도 확인했습니다.

  1. 01공시자료 입력금액·통화·만기일과 판단의 출처 확인
  2. 02AI 분석 응답원문에 없는 추세·인과 표현을 대조
  3. 03후처리·단위 변환이번 저장 실패가 발생한 단계
  4. 04DB 저장기존 273건 유지, 실패 2건 복구
복구 판단

분석 응답 자체는 남아 있었으므로 모델을 다시 호출하지 않았습니다. 단위 처리 오류를 수정한 뒤 실패한 응답 2건만 다시 처리했습니다. 재실행 전반의 중복 저장 방지나 모든 실패 유형의 자동 복구를 보장한다는 뜻은 아닙니다.

제가 맡은 일

검증, 복구, 시세조사 흐름을 맡았습니다

01

원문 근거를 확인하는 보고서 검증

금액·통화·만기일과 판단 근거를 입력 자료와 대조했습니다. 글머리표별 근거 형식과 문체를 정리하고, 2차 교정 과정에서 사실·수치·원문의 의미가 보존되는지 확인하는 기준을 보완했습니다.

02

기존 응답을 재사용한 오류 복구

Batch 결과의 외화 단위 처리 오류를 수정하고 기존 응답을 재처리했습니다. 기존 273건을 유지하고 실패 2건을 추가 AI 호출 없이 복구해 최종 275건의 DB 저장을 완료했습니다. 모델·추론 강도별 품질, 처리 시간, 토큰 사용량과 비용도 비교했습니다.

03

주변 거래 조회와 비교표 자동화

주소나 지도에서 조사 위치를 지정하고 기간·반경·유형으로 거래를 찾도록 개발했습니다. 실거래가·건축물대장·KB 정보를 연결하고, 면적 환산·전용률·평단가 계산과 내보내기를 정비했습니다.

오류 전후

다시 생성하지 않고 저장 단계만 고쳤습니다

오류 당시AI 응답 수신 → 외화 단위 처리 오류 → 2건 저장 실패

이 단계의 실패를 보고서 생성 품질 문제와 구분했습니다.

수정 뒤기존 응답 재사용 → 단위 처리 수정 → 실패 2건 저장

기존 273건과 합쳐 해당 Batch의 최종 저장 결과가 275건이 됐습니다.

공개 설명을 위한 단계 도식입니다. 회사의 실제 입력값·응답·고객 정보는 포함하지 않았습니다.

수치마다 대상과 시점이 다릅니다. 275건은 한 Batch의 최종 저장 수이고, 35건은 기존 조사표의 거래 표본입니다. 200개 대조와 58개 재검토는 별도 보고서 검증 과정입니다. 모델·추론 강도별 품질·처리 시간·토큰·비용도 비교했지만, 이 페이지에는 동일 조건의 공개 수치가 없어 우열이나 절감률을 주장하지 않습니다. 회사 내부 원문·고객 정보·소스코드는 공개하지 않았습니다.
