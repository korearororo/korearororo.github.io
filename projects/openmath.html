문제

생성에 필요한 참조 문항이 학년과 단원에 맞아야 했습니다. 데이터의 형식도 생성 단계가 기대하는 형식과 달랐고, 조건을 엄격하게 적용하면 검색 결과가 없는 경우가 있었습니다.

해결 방향

JSONL을 공통 문항 형식으로 변환하고, 구조화 조건과 텍스트 점수로 검색했습니다. 검색 결과가 없을 때 조건을 완화해 다시 조회하고, 참조 문항을 생성 흐름과 검증 화면까지 전달했습니다.

MY CONTRIBUTION

제가 구현한 부분

01

데이터 형식 통일

AI Hub 기반 정규화 JSONL을 한 줄씩 읽고 quality.is_usable이 false인 레코드를 제외했습니다. 원문·정답·해설·교육과정 정보를 SourceProblem으로 변환하고, 분류 정보와 검색 텍스트는 내부 인덱스에 보존했습니다.

02

조건 필터와 결과 정렬

학교급·학년·단원·유형·난이도·성취기준 매핑 신뢰도로 후보를 거릅니다. 단원과 출제 의도에 대한 텍스트 일치도를 점수에 반영하며, 동점은 문항 ID로 정렬합니다.

03

별도 브랜치에서 생성 흐름 연계

PR #10에서 검색 문항과 source_refs를 출제 의도 분석 및 생성 흐름에 전달하고 SSE로 진행 상태를 보내도록 구현했습니다. RAG와 출제 의도 단계까지 확인했으며, 해당 PR은 main에 병합되지 않았습니다.

DESIGN & TRADE-OFFS

구조와 구현 판단

데이터 흐름

정규화 JSONL → 사용 가능 레코드 → SourceProblem → 조건 필터·텍스트 점수 → 참조 문항 / source_refs

검색 방식의 범위

교육과정 등 구조화 조건은 필터로, 단원·출제 의도 텍스트는 점수로 다룹니다. 현재 구현은 텍스트 점수 기반이며, 임베딩 기반 검색과의 비교는 후속 평가 과제입니다.

일관된 결과

동점 결과는 문항 ID로 정렬합니다. 같은 점수의 문항 순서가 바뀌는 경우를 줄여 검색 결과를 비교할 수 있게 했습니다.

결과가 없을 때

엄격한 조건에서 결과가 없으면 재검색 조건을 완화합니다. 조건 완화가 검색 품질을 얼마나 바꾸는지는 별도의 평가가 필요합니다.

PROBLEM SOLVING

조건을 모두 적용했는데 결과가 없을 때

01

상황

학년·단원·유형·난이도를 모두 제한하면 참고 문항을 찾지 못하는 경우가 있었습니다.

02

처리

엄격한 조건으로 먼저 검색하고, 결과가 없으면 조건을 단계적으로 완화하도록 구성했습니다.

03

확인

재검색 로직과 RAG → 출제 의도 단계의 SSE 이벤트, 참조 문항 전달을 검증했습니다.
