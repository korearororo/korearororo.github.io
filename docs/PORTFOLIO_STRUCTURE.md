홈은 목적·문제·담당 범위·판단·확인 결과를 짧게 소개하고, 상세 사례는
문제 → 본인 역할 → 구현 판단 → 실패와 수정 → 확인 결과와 한계 순서로 읽는다.
상세에서 요약 문장을 반복하기보다 코드·입출력·전후 결과를 연결한다.

## 대표 사례와 순서

공통 기본본은 실제 업무의 문제 발견과 복구 판단을 보여주는 유동산을 첫 사례로 둔다.
OpenMath는 공개 PR과 재현 가능한 입력·결과, Pokechi는 저장 설계와 실행 시연으로 이어진다.
관심 직무는 소프트웨어 개발·AI 응용으로 유지하며 특정 채용 공고나 회사명을 소개 문구에 넣지 않는다.

지원처별 제출본은 공고를 확인한 뒤 사례 순서와 강조점을 바꾼다.
AI 응용은 유동산의 근거 검증과 OpenMath의 검색을 먼저 설명하고,
상태 관리·백엔드 경험을 강조할 때는 Pokechi의 버전 비교와 병합 제약을 앞당길 수 있다.
이 권고는 공통 사이트의 기본 순서를 자동으로 바꾸라는 뜻은 아니다.

## 근거와 공개 범위

- 유동산: 입력에 없는 판단의 검증, 저장 실패 2건 복구와 최종 275건 저장,
  기존 조사표 5개의 실거래 표본 35건 대조를 구분한다. 회사 원문·코드·화면은 공개하지 않는다.
- OpenMath: 검색 PR #8과 후속 #12·#13은 병합, 별도 연계 #10은 전체 미병합이다.
  공개 seed 7건·질의 3개는 필터 동작 재현이며 전체 검색 품질 평가가 아니다.
- Pokechi: 카드 이미지는 렌더러의 예시 진행값이다. 44초 영상은 로컬 기능 시연이다.
  로그인·서버 동기화 영상으로 설명하지 않고, 다른 물리 PC 검증과 경험치 합산 제약을 남긴다.

각 사례의 별도 편집 단계에서 이어간다.
